# Reproducibility and Integrity Notes

## One-Command Verification

```bash
python scripts/verify.py
```

This command runs the test suite, a baseline smoke run, an MTGS forced-abort
smoke run, and a dry-run experiment matrix check.

## Environment

The committed environment summary is in `env_manifest.txt`. Every experiment
directory generated by `scripts/run_experiment.py` also includes
`env_fingerprint.json` with Python, platform, Git commit, PyTorch, NumPy, and
CUDA availability.

## Artifacts

Local report artifacts are generated from `experiments/results/local_report`.
Processed deliverable artifacts are:

- `docs/results_summary.md`
- `docs/figures/throughput_comparison.png`
- `docs/figures/ettr_comparison.png`

## Claim Traceability

Every plotted or tabulated local result maps to a run id in the generated
summary table. Cloud claims should only be added after the corresponding raw run
directory is archived with the same schema.

## Local Constraint

This Windows CPU-only PyTorch build cannot create a usable local Gloo process
group, so `scripts/ddp_mtgs_smoke.py` records an explicit environment skip here.
The final multi-node validation path is therefore the cloud topology and
`torchrun` workflow defined in `infra/cluster_topology.yaml` and
`docs/deliverable3_environment.md`.

## External Influence Attribution

The implementation relies on public PyTorch and Hugging Face APIs. The citation
ledger records those API influences and distinguishes them from MTGS-specific
code.
